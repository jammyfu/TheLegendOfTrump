# 游戏 QA 与修复记录 · 2026-09-10

## 测试版本与方法

基于 `66022e0`，同时检查了当前工作区正在开发的装备拾取、主题和手机 HUD。修复单独整理为提交候选，保留其他任务的未提交改动。使用独立的 4440/4441 测试服务，没有重启用户的 4439 服务。

Chrome / Playwright，单 worker，Three.js 使用 SwiftShader 软件渲染。桌面 1440×900、1024×768；触屏布局 390×844、360×740、844×390。真实按键、鼠标和 CDP 多点触控结合确定性场景准备；截图检查实际 WebGL 画面。战斗、机关、Boss 和结局测试会使用传送、调整敌人状态等准备步骤，不等于无辅助完整通关。

## 测试基础设施修正

- 战斗用例通过真实宝箱交互准备剑盾；宝箱坐标从游戏配置读取，避免装备改动后旧坐标导致误报。
- 降落点宝箱验证实际开启结果，兼容其由弓箭装备改为补给的流程。
- 手机武器切换在取得武器后验证，不要求空手阶段显示切换按钮。
- HUD 测试统一遵守 `GAME_URL`，修正原先固定访问 4439 的问题，并加载当前可选的手机 HUD 样式。
- 镜头墙边测试检查碰撞安全距离，替换“无论墙壁多近都必须离角色超过 5 米”的过时断言。
- 旋转斩测试隔离自动锁定跟随，避免把合法的自动镜头转向误判为鼠标拖动。
- 片头测试先等模型实际可见再冻结时间；通关用例等书桌真正可交互后按 E，消除依赖机器速度的固定延时。

首轮浏览器 29 项中 19 项通过、10 项失败。失败经逐一检查，包括真实触屏问题和上述失效前置条件；没有通过删掉失败用例掩盖问题。菜单导航与陶罐落地另补了浏览器和逻辑回归。

## 性能复测

场景：主角 `(-20,15)`，正常敌人 AI，固定 `1/60` 秒模拟步长，仅保持主角无敌。预热 500 次，正式每轮 5,000 次，优化前后交替各 3 轮。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 第 1 轮 | 2077.87 ms | 931.23 ms |
| 第 2 轮 | 2330.87 ms | 958.16 ms |
| 第 3 轮 | 2621.04 ms | 1124.33 ms |
| 中位耗时 | 2330.87 ms | 958.16 ms |

该场景模拟 CPU 耗时降低约 59%。这不是整个游戏帧率，也不包含 GPU 渲染；Chrome 软件渲染结果不能当成手机真机性能承诺。复测当前版本：`node --import tsx scripts/benchmark-simulation.ts`。
